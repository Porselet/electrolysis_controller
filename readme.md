# Electrolysis Controller

Устройство автоматического управления циклом «наполнение — выдержка — сброс»
электролизера с азотной подушкой.

Версия 2. Добавлены: интерактивный UI с кнопками, редактирование уставок,
сохранение в EEPROM.

## Что делает

Управляет двумя клапанами (V1 — вход от баллона N2, V2 — сброс) по
циклическому алгоритму:

1. **FILL** — открыть V1, закрыть V2. Ждать, пока давление P >= FILL (по умолчанию 20 атм).
2. **HOLD** — закрыть V1, закрыть V2. Ждать HOLD (по умолчанию 60 минут).
3. **VENT** — закрыть V1, открыть V2. Ждать, пока P <= 0.5 атм.
4. Повтор с шага 1.

Давление измеряется двумя датчиками 4-20 мА, установленными в одной точке.
При аварии — переход в терминальное состояние с сиреной и безопасной
конфигурацией клапанов.

Параметры FILL и HOLD редактируются с устройства и сохраняются в EEPROM.

## Структура проекта

| Файл | Назначение |
|---|---|
| `electrolysis_controller.ino` | Главный файл. Связка модулей, setup()/loop(), обработка кнопок, выбор экрана. |
| `config.h` | Все константы: пины, параметры датчиков, пороги алгоритма и аварий, диапазоны и шаги уставок. |
| `sensors.h/.cpp` | Чтение датчиков 4-20 мА, медианный фильтр, диагностика петли. |
| `safety.h/.cpp` | Выбор рабочего давления, обнаружение аварий и деградации, безопасная конфигурация клапанов. |
| `algo.h/.cpp` | Конечный автомат цикла (FILL / HOLD / VENT). Здесь же макросы STEP / END_STEP / WAIT_UNTIL / WAIT_SECONDS / NEXT. |
| `valves.h/.cpp` | Управление GPIO: клапаны и сирена. |
| `buttons.h/.cpp` | Чтение кнопок KeyShield с антидребезгом. Возвращает фронт нажатия. |
| `settings.h/.cpp` | Уставки в оперативке + чтение/запись в EEPROM. Автосохранение по таймеру. |
| `ui.h/.cpp` | Вывод на LCD 16x2: три экрана + аварийный. |
| `telemetry.h/.cpp` | Serial-лог для отладки при пуско-наладке. Отключается флагом в config.h. |

## UI: экраны

Листание — кнопкой **SELECT** по кругу: Экран 0 -> Экран 1 -> Экран 2 -> Экран 0.

### Экран 0: основной

    FILL T=00:12:34
    P= 12.3 dP=  0.1

Показывает текущий шаг, таймер с начала шага, рабочее давление, расхождение
датчиков. При деградации одного датчика вместо dP выводится `P1 OPEN`
или `P2 OPEN`.

### Экран 1: датчики

    1= 12.3 OK
    2= 12.4 OK

Показания обоих датчиков и их статус: OK / OPEN / SHORT / RAIL_L / RAIL_H.

### Экран 2: уставки

    >FILL 20.0 atm
     HOLD   60 min

Курсор `>` показывает активное поле. Управление:

| Кнопка | Действие |
|---|---|
| UP | увеличить текущее поле (FILL +0.5 атм, HOLD +1 мин) |
| DOWN | уменьшить текущее поле |
| LEFT | курсор на FILL |
| RIGHT | курсор на HOLD |
| SELECT | сохранить в EEPROM и перейти на экран 0 |

Диапазоны:

- FILL: 0.0 .. 25.0 атм (шаг 0.5)
- HOLD: 0 .. 1440 мин (шаг 1 мин)

HOLD хранится в секундах, на экране выводится в минутах.

## Сохранение уставок

Уставки хранятся в EEPROM:

| Адрес | Данные | Размер |
|---|---|---|
| 0 | magic (0xEC02) | 2 байта |
| 2 | FILL, float | 4 байта |
| 6 | HOLD, uint32 (секунды) | 4 байта |

При старте `settings_load()` читает EEPROM. Если magic не совпал или
значения вне диапазона — берутся дефолты из `config.h`.

Сохранение происходит:

- при уходе с экрана уставок (нажатие SELECT);
- автоматически через 10 секунд после последнего изменения.

## Алгоритм: как читать код

Основной цикл описан в `algo.cpp` в функции `algo_tick()`. Используются
макросы для читаемости:

    STEP(FILL) {
        V1(OPEN); V2(CLOSE);
        WAIT_UNTIL(P >= g_fill_threshold);
        NEXT(HOLD);
    } END_STEP

- `STEP(NAME)` — открывает блок шага.
- `V1(...)`, `V2(...)` — устанавливают целевое состояние клапанов.
- `WAIT_UNTIL(условие)` — взводит флаг перехода при истинности условия.
- `WAIT_SECONDS(N)` — то же, но по таймеру шага.
- `NEXT(NAME)` — объявляет, куда переходить.
- `END_STEP` — выполняет переход, если флаг взведён.

Логика неблокирующая: каждый вызов `algo_tick()` — один тик.

## Аварии

Проверяются в порядке приоритета (первое сработавшее — итоговое):

1. **Overpressure** — `P > P_MAX` по любому валидному датчику.
2. **Sensor fault** — оба датчика невалидны.
3. **Sensor mismatch** — датчики валидны, но `|P1 - P2| > P_DIFF_MAX`.

Реакция:

| Авария | V1 | V2 |
|---|---|---|
| Overpressure | закрыть | открыть (стравить) |
| Sensor fault | закрыть | оставить как был |
| Sensor mismatch | закрыть | оставить как был |

Дополнительно:

- Сирена включается непрерывно.
- Рабочий цикл останавливается.
- Выход из аварии — только перезапуск питания (в `loop()` стоит `while(1)`).
- На LCD выводится аварийный экран с причиной.

## Деградация

Отказ одного датчика при живом втором — не авария, а деградация:

- Работа продолжается по валидному датчику.
- Сирена не включается.
- На основном экране выводится `P1 OPEN` или `P2 OPEN`.
- На экране датчиков виден статус каждого.

## Датчики: диагностика

Петля 4-20 мА. Признаки отказа:

| Признак | Условие | Статус |
|---|---|---|
| Сырое напряжение у нижней рельсы | V < 0.1 В | RAIL_LOW |
| Сырое напряжение у верхней рельсы | V > 4.9 В | RAIL_HIGH |
| Обрыв петли | I < 3.6 мА | OPEN |
| Перегруз / КЗ | I > 21 мА | SHORT |
| Норма | 3.6 <= I <= 21 | OK |

Фильтр: медиана из 9 отсчётов АЦП. Отсекает импульсные выбросы.
Подтверждение статуса не используется — если медиана показала обрыв,
это реальная авария.

## Настройка параметров

Часть параметров редактируется с устройства (FILL, HOLD), часть — только
в `config.h`.

### Редактируется с устройства (хранится в EEPROM)

| Параметр | Назначение | Диапазон | Шаг | По умолчанию |
|---|---|---|---|---|
| FILL | Порог окончания накачки, атм | 0.0 .. 25.0 | 0.5 | 20.0 |
| HOLD | Время выдержки, мин | 0 .. 1440 | 1 | 60 |

### Только в config.h

| Параметр | Назначение | По умолчанию |
|---|---|---|
| VENT_THRESHOLD | Порог окончания сброса, атм | 0.5 |
| P_MAX_BAR | Порог аварии overpressure, атм | 23.0 |
| P_DIFF_MAX | Допустимое расхождение датчиков, атм | 1.0 |
| P_RANGE | Верхняя граница датчика, атм | 25.0 |
| R_SHUNT | Сопротивление шунта, Ом | 150.0 |
| TELEMETRY_ENABLED | Serial-лог (1 — вкл, 0 — выкл) | 1 |

## Открытые вопросы

- P_MAX — 22 или 25 атм? (сейчас 23 как компромисс)
- P_DIFF_MAX — 0.5 или 1.0 атм? (зависит от класса точности датчиков)
- VENT_THRESHOLD — 0.5 атм — финальное?
- P_RANGE — реальный диапазон датчика?

## Запуск

1. Открыть `electrolysis_controller.ino` в Arduino IDE.
2. Все .cpp/.h подхватятся автоматически (папка скетча).
3. Выбрать плату: Arduino Uno.
4. Прошить.
5. При необходимости — смотреть Serial на 115200 бод.

## Рекомендации заказчику

- Механический предохранительный клапан на электролизере — обязателен.
  Софт не является последней линией обороны.
- Дроссель на линии сброса — для плавного стравливания (пневмоклапаны
  не работают в ШИМ-режиме).
- Проверить точность шунт-резисторов — от них зависит точность измерения.
